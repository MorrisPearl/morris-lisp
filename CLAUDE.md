All source code (in any language) should be written in a straight
forward way, so that someone can read the code and easily understand
what it is doing and how it work.

Numeric constants should usually have names (reasonable exceptions are
0 and 1.  12 is okay for months in a year, 100 is okay for dealing
with percentages).  We can have more exceptions if we have some
reason.

The purpose of the software is to help people understand things.

All source files should be checked in to the main branch of git, and
committed, and pushed to github, unless you are told to use a branch.

The users almost always use the lisp interpreter through a Jupyter
notebook.  Everything should be written with the Jupyter notebook
interface in mind unless otherwise specified.
